# Система анализа ГРП

## О программе

Настольная программа для учёта и оценки остаточного ресурса оборудования
газорегуляторных пунктов (ГРП). Ведёт базу ГРП вместе со сведениями паспорта
объекта, составом оборудования и запчастей, журналом замен, журналом
технических диагностирований и протоколом проверок (режим, допуск и факт
в кПа с результатом «норма / отклонение от нормы»); считает ресурс
по пяти методикам из папки `docs/`; назначает срок следующего
диагностирования; печатает отчёт
по форме 6.2 в Word и выгружает журнал замен в Excel.

Один расчёт — один ответ: и экран, и Word-отчёт берут числа из общего ядра
(`logic/algorithms.py`), а всю арифметику сроков считает один модуль
(`core/lifetimes.py`), поэтому показания интерфейса и отчёта совпадают.

Пользователь — инженер производственно-технического отдела: программа
заменяет ручной расчёт сроков в Excel и служит обоснованием для планирования
замен и назначения даты следующего диагностирования.

Данные хранятся в PostgreSQL на своём сервере; наружу программа ничего
не отправляет. Отчёты помечаются «ДСП».

**Технологии:** Windows, Python 3.10+ (tkinter), PostgreSQL 13+,
`psycopg2`, `python-docx`, `openpyxl`, `pdfplumber`.

## Возможности

* База ГРП с паспортными сведениями объекта (адрес, регистрационный номер,
  даты приёмки и ввода в эксплуатацию, тип регулятора, материалы, покрытие,
  изготовитель, газопровод, «закольцован с»).
* Учёт оборудования в составе ГРП и запчастей в составе оборудования
  (норма, признак заменяемости, дата установки, обозначение по каталогу).
* Паспорт единицы оборудования: тип (модель), изготовитель, диаметр условный
  ДУ, количество, номер по схеме, дата монтажа, назначенный срок службы
  («не нормируется», если документация срока не назначает), наработка,
  примечание. Идентификаторы записей пользователю не показываются:
  в таблицах идёт номер строки.
* Журнал замен запасных частей с влиянием на срок: «только журнал»,
  «сбросить срок запчасти», «заменить оборудование целиком».
* Журнал отказов ГРП: дата выявления, тип события, причина, критичность,
  признак устранения, документ и примечания с номером акта, рекомендациями
  и приложенным фото.
* Каталог оборудования с типовыми составами запчастей и импортом
  из PDF-альбома завода-изготовителя.
* Пять методик расчёта остаточного ресурса, слабое звено, срок следующего
  диагностирования, продление срока заменой запчастей.
* Технические коэффициенты A, B, C → K по журналу диагностирований,
  редактор весов и ручных поправок.
* Экран «Техническое диагностирование»: что и с каким допуском проверяли —
  режим, допуск и факт в кПа, результат «норма / отклонение от нормы».
* Отчёт по ГРП в Word (титульный лист, сведения о ГРП, форма 6.2, подписи)
  и выгрузка журнала замен в `Замены.xlsx`.
* Проверки данных: чего не хватает, что принято по умолчанию, какие элементы
  не вошли в расчёт (замечания на экране расчёта).

## Бизнес-требования

| № | Требование | Как выполнено |
|---|---|---|
| БТ-1 | Обоснованная оценка остаточного ресурса оборудования ГРП по утверждённым методикам, а не «на глаз» | Пять методик (`logic/algorithms.py`), расчёт по формулам методик из `docs/`, трассировка каждой величины |
| БТ-2 | Назначение срока следующего диагностирования по результату оценки | `T диагн. = min(Z_ГРП × K_запаса; T_макс)`, T_макс по умолчанию 5 лет (Правила МЧС РБ) |
| БТ-3 | Единое хранилище сведений о ГРП вместо разрозненных таблиц | База PostgreSQL: ГРП с паспортом, оборудование, запчасти, журналы замен и диагностик |
| БТ-4 | Учёт замен запасных частей и их влияния на срок службы | Журнал замен; эффекты «сбросить срок запчасти» и «заменить оборудование целиком»; откат эффекта при правке и удалении записи |
| БТ-5 | Типовые составы запчастей из заводского альбома — без ручного ввода | Каталог оборудования, импорт «Альбома запчастей по газу», автоподстановка состава при добавлении оборудования |
| БТ-6 | Отчётность: форма 6.2 в Word для приложения к отчёту по ГРП | `integration/word_report_pg.py`: титульный лист, сведения о ГРП, форма 6.2 по двум методикам, подписи |
| БТ-7 | Ведение журнала замен в привычной форме Excel | Выгрузка `Замены.xlsx`, лист на каждый ГРП, обновление автоматически при каждой замене |
| БТ-8 | Прозрачность расчёта: специалист должен видеть, из чего получилось число | Вкладки «Коэффициенты» и «Исходные данные», таблица «Как посчитано», замечания к данным |
| БТ-9 | Непротиворечивость: на экране и в отчёте — одни и те же числа | Общее ядро расчёта, единый модуль сроков, тест `tests/test_report_form62.py` сверяет форму 6.2 с расчётом |
| БТ-10 | Работа в закрытом контуре, служебный характер данных | Локальная БД, нет внешних сервисов и авторизации через интернет; отчёт помечается «ДСП» |
| БТ-11 | Пригодность для проверки и сопровождения | 333 автотеста без БД и Tkinter, демонстрационные данные, документированная установка и сборка `.exe` |

## Функциональные требования

**ГРП и паспорт**

* ФТ-1. Создание, выбор, редактирование и удаление ГРП; тип, число линий
  редуцирования, фактический и проектный срок службы.
* ФТ-2. Ввод сведений паспорта объекта (раздел 1): 12 полей, включая даты
  приёмки и ввода в эксплуатацию в виде «01.1981». Незаполненное поле
  печатается в отчёте прочерком.
* ФТ-3. Один ГРП — рабочий: пункты меню действий с оборудованием, заменами
  и отчётом доступны только при выбранном ГРП.

**Оборудование и запчасти**

* ФТ-4. Состав оборудования задаётся в форме ГРП при его создании и правится
  при редактировании, а также с рабочего экрана: добавление, правка, удаление,
  дата монтажа. Паспортные сведения единицы: наименование, тип
  (модель), изготовитель, диаметр условный ДУ, количество, номер по схеме,
  дата монтажа (установки), назначенный срок службы, назначенная и
  фактическая наработка, примечание — хранятся текстом и в расчёте
  не участвуют. Вместо числа лет в назначенном сроке допускается
  «не нормируется»: тогда фактическая наработка показывается прочерком.
  При сохранении состав запчастей подставляется из одноимённой
  модели каталога.
* ФТ-5. Ведение состава запчастей оборудования: добавление с датой установки
  и её последующая правка (даты снятия в формах нет — запчасть ставят, а не
  снимают; снятие ставит замена), норма срока службы, переключение признака
  «заменяемая», удаление из состава. Идентификаторы записей пользователю не показываются:
  в таблицах оборудования, запчастей, журнала замен и истории диагностик
  первой графой идёт номер строки 1..n.
* ФТ-6. Срок службы оборудования определяется его заменяемыми запчастями
  (минимальный остаток), собственного срока у оборудования нет.
* ФТ-7. Проверка оборудования по нормам с выдачей статуса «срок истёк» /
  «требует внимания» / «в пределах срока».

**Замены**

* ФТ-8. Журнал замен запасных частей по форме ремонтного журнала: номер,
  дата замены/ремонта, номер по схеме, запчасть в этом оборудовании, причина,
  наработка до замены/ремонта, остаточный ресурс после ремонта (лет),
  документ-основание, ФИО ответственного, вид работ, примечание. Прежние
  реквизиты («Лида.xlsx»: тип, модель, производитель, номер запчасти)
  сохраняются в записи и выгружаются в Excel, но в таблице не показываются.
* ФТ-9. Выбор влияния записи на срок: только журнал / сбросить срок
  запчасти / заменить оборудование целиком.
* ФТ-10. Операция «Заменить запчасть»: закрытие активной записи и создание
  новой с датой замены; срок отсчитывается заново. Заменять можно только
  запчасти с признаком «заменяемая».
* ФТ-11. Операция «Заменить оборудование полностью»: снятие прежнего
  оборудования, создание нового, перенос состава запчастей с новыми датами.
* ФТ-12. Правка и удаление записи журнала с откатом её влияния на сроки
  и с обновлением Excel.

**Отказы**

* ФТ-13. Информация по отказам: список отказов выбранного ГРП в порядке
  граф — номер, дата выявления, тип события (например, «нарушение работы
  оборудования»), причина, критичность (словами: низкая, средняя, высокая),
  устранён (да/нет), документ, куда отказ вносится (по умолчанию «Аварийный
  журнал»), примечания. Лишних граф в таблице нет.
* ФТ-14. Добавление, правка и удаление записи об отказе. Критичность и
  признак устранения выбираются словами из списка, тип события —
  свободная строка с подсказкой; в графы с ограниченным набором значений
  чужой текст не записывается. Список показывает свежие отказы сверху.
* ФТ-15. Примечания хранят номер акта и рекомендации, а к записи
  прикладывается фото: снимок хранится в базе, показывается внешней
  программой и удаляется вместе с записью.

**Техническое диагностирование**

* ФТ-16. Отдельный экран «Техническое диагностирование»: таблица проверок
  выбранного ГРП в порядке граф — номер, дата, оборудование,
  проверяемый параметр, режим (кПа), допуск мин (кПа), допуск макс (кПа),
  факт мин (кПа), факт макс (кПа), результат (норма / отклонение от нормы)
  и примечание. Лишних граф в таблице нет.
* ФТ-17. Добавление, правка и удаление записи проверки; список показывает
  свежие проверки сверху. Числа в кПа вписываются с запятой или точкой,
  чужой текст в этих графах не сохраняется. Результат программа выводит
  по допуску и факту, а специалист может выбрать его вручную — выбранный
  вручную не переписывается.

**Каталог и импорт**

* ФТ-18. Каталог оборудования (служебный ГРП) с моделями и типовыми
  составами запчастей; добавление модели без дат — срок определится
  запчастями. Наименование вписывается своими словами, без списка готовых:
  вместо подсказки программа проверяет, нет ли в каталоге такой же модели,
  и повторную не сохраняет.
* ФТ-19. Импорт запчастей и моделей из PDF-альбома: разбор таблиц,
  заполнение справочника запчастей, простановка признака заменяемости
  и обозначений, отчёт о единицах оборудования без совпадения. Страницы
  разборки узлов моделью не становятся — в каталоге только оборудование.

**Расчёт**

* ФТ-20. Пять методик расчёта; переключение методики и пересчёт по кнопке.
* ФТ-21. Остаточный ресурс ГРП: для методик со слабым звеном — минимум
  по критическим элементам, для остальных — среднее арифметическое.
* ФТ-22. Слабое звено с указанием запчасти, которая держит ресурс.
* ФТ-23. Срок следующего диагностирования и рекомендуемая дата.
* ФТ-24. Продление срока: ползунок цели, лестница замен запчастей слабого
  звена с приростом на каждом шаге.
* ФТ-25. Редактор весов (α, β, θ, δ, K запаса, T макс) и ручных поправок
  коэффициентов; возврат к методическим значениям; пересчёт.
* ФТ-26. Трассировка: таблица «Как посчитано» по каждому элементу —
  база Z и вариант её получения, коэффициенты, ресурс, формула.
* ФТ-27. Замечания к данным и расчёту: чего не хватает, что принято
  по умолчанию, какие элементы не вошли и почему.

**Отчётность и данные**

* ФТ-28. Отчёт по ГРП в Word: титульный лист, раздел 1 «Сведения о ГРП»,
  раздел 2 «Результаты расчёта остаточного ресурса» с формой 6.2, подписи.
* ФТ-29. Выгрузка журнала замен в `Замены.xlsx` — лист на каждый ГРП,
  посторонние листы файла сохраняются.
* ФТ-30. Демонстрационные данные: четыре ГРП-сценария и каталог; создаются
  один раз и не затирают пользовательские данные.

## Функционал

Программа однодокументная: одно главное окно, и каждый пункт меню открывает
в нём свой экран. Постоянных экранов шесть — «Рабочее ГРП», «Каталог
оборудования», «Замены (ремонт)», «Информация по отказам», «Технические
коэффициенты», «Техническое диагностирование»; остальные
(выбор и удаление ГРП, форма ГРП, отчёт,
импорт из PDF, обновление Excel, расчёт алгоритмов) собираются заново при
каждом открытии — они зависят от выбранного ГРП и от свежих данных базы.
Отдельных окон настроек, поиска, фильтров и журнала действий нет; авторизации
нет — доступ к базе задаётся переменными окружения. Всплывающие окна остались
только там, где действие запускает кнопка внутри экрана (добавить единицу
оборудования, заменить запчасть, сохранить файл). Результат каждой операции
пишется в строку состояния внизу окна.

### 1. Главное окно

* Верхняя панель: кнопка `☰` (левое меню), бейдж выбранного ГРП, справка
  `❓` с быстрым стартом, строка состояния.
* Левое меню по группам:
  * **ГРП** — создать, выбрать, редактировать, удалить;
  * **Действия с выбранным ГРП** — оборудование и запчасти, замены (ремонт),
    информация по отказам, отчёт по ГРП (Word), расчёт алгоритмов,
    технические коэффициенты, техническое диагностирование;
  * **Справочники** — каталог оборудования.
* Импорта из PDF-альбома и обновления файла Excel в меню нет: это действия
  внутри своих экранов — «📂 Загрузить PDF-альбом» в каталоге и «📥 Обновить
  Excel» в журнале замен; файл `Замены.xlsx` и без кнопки перезаписывается
  при каждой правке замен.
* Пункты, требующие ГРП, гаснут, пока ГРП не выбран.
* Экран «Выбрать ГРП»: таблица с ID, типом, числом линий, сроками,
  количеством оборудования и замен; служебные каталоги в список не попадают.
  Кнопка на экране одна — «🗂 Выбрать»: список пересобирается при каждом
  открытии, а выбранный ГРП сам возвращает на рабочий экран. Экран «Удалить
  ГРП» — та же таблица с кнопками удаления, обновления и закрытия.
* Каждый экран прокручивается в основной области окна; возврат на рабочий
  экран — выбор ГРП из списка, кнопка «Закрыть» на самом экране (где она
  есть) или пункт меню.
* Все таблицы прокручиваются и по вертикали, и по горизонтали: нижний
  ползунок открывает правые графы (журнал замен, оборудование и запчасти,
  каталог, история диагностик, списки ГРП), когда они не помещаются в окно.
* Отдельного экрана статистики нет: сведения о количестве запчастей и замен
  выводятся в таблицах разделов.

### 2. ГРП и паспорт объекта

Создание и редактирование ГРП: тип ГРП (наименование объекта), количество
линий редуцирования, фактический и проектный срок службы — сроки вводятся
свободно, как «7 лет 4 мес», «7,3» или «7,3 года». Ниже — блок «Сведения
о ГРП (паспорт объекта)»: адрес, регистрационный номер, дата приёмки
в эксплуатацию, дата ввода в эксплуатацию (или дата последней полной замены
ГРП), тип регулятора, материал корпуса, материал труб, наличие и тип
антикоррозионного покрытия, завод-изготовитель, газопровод, «закольцован с».

Описания полей собраны в одном месте — `core/grp_passport.py`; оттуда же
берут подписи и порядок полей и форма ввода, и Word-отчёт, поэтому форма
и отчёт не разъезжаются. Даты приёмки и ввода хранятся текстом: в паспорте
они указаны с точностью до месяца («01.1981», «10.2007»), а не числом.

Ниже паспорта — блок «Оборудование в составе ГРП»: здесь выбирается, какие
единицы стоят внутри ГРП (наименование подсказывается из каталога, у каждой
своя дата монтажа и паспортные сведения). Состав задаётся при
создании ГРП и правится при редактировании, а также с рабочего экрана.
При сохранении состав запчастей подтягивается из каталога, поэтому после
создания ГРП он сразу готов к расчёту.

Строка списка нумеруется по порядку (1..n), а не по идентификатору записи
в базе; рядом идут графы паспорта единицы. Описание полей — в одном месте,
`core/equipment_card.py`: оттуда берут подписи и порядок и таблица
оборудования, и список в форме, и отчёт по оборудованию, поэтому ввести
можно ровно то, что потом видно. Числа паспорта (назначенный срок службы,
назначенная и фактическая наработка) хранятся текстом, как и даты паспорта
ГРП: они переносятся из документации как есть и в расчёте не участвуют —
срок оборудования по-прежнему задают заменяемые запчасти (см. раздел 3).

Документация назначает срок службы не всегда: в графе «Назначенный срок
службы, лет» тогда пишут «не нормируется» (в любом написании — приведение к
одному виду делает `core.equipment_card.norm_life`). У такой единицы
фактическая наработка в таблице показывается прочерком: срок не нормирован,
сравнивать наработку не с чем. В паспорте значение остаётся — прочерк это
правило показа, а не удаление введённого числа.

Карточка «Информация о ГРП» показывает имя, сроки, количество оборудования
и замен, адрес и регистрационный номер.

### 3. Оборудование и запчасти

Карточка «Оборудование»: список единиц оборудования. Графы — номер по
порядку, наименование, тип (модель), изготовитель, диаметр условный ДУ,
количество, номер по схеме, дата монтажа (установки), назначенный срок
службы, назначенная и фактическая наработка, примечание (описание полей —
`core/equipment_card.py`). Идентификатор записи в таблице не показывается,
даты снятия нет: её ставит приложение, когда единицу заменяют целиком, —
в паспорте единицы эта графа не заполняется и не показывается. Действия:

* добавить оборудование (та же форма, что в составе ГРП, — второй формы
  с другим набором полей нет; запчасти подтянутся из каталога);
* изменить выбранную единицу;
* удалить оборудование;
* проверить по нормам.

Остатка срока в списке нет сознательно — он зависит от запчастей и виден
в панели запчастей и в расчёте. Граф в таблице тринадцать, поэтому в окне
обычной ширины правые достаёт нижний ползунок.

Назначенный срок службы вводится числом лет («20», «20 лет») либо словами
«не нормируется» — иные записи форма не принимает, потому что отличить
«20 лет, продлён» от описки нельзя. У единицы с неназначенным сроком
фактическая наработка в таблице заменяется прочерком (правило перечислено
в `core/equipment_card.py`), а значение наработки в паспорте сохраняется.

Карточка «Запчасти выбранного оборудования»: номер по порядку, наименование
запчасти, обозначение по каталогу, признак «заменяемая», дата установки или
замены. Действия:

* добавить запчасть: спрашивается только дата установки (пустая — значит
  «как у оборудования»), даты снятия в этой форме нет — снимают запчасть
  заменой, а не постановкой в состав;
* изменить дату установки (кнопка «✏ Дата установки»); дата снятия, если
  она уже стоит, при этом сохраняется — правка даты установки снятие
  с учёта не отменяет;
* изменить норму срока службы (свободный ввод: «7 лет 4 мес» или «7,3»);
* переключить признак «заменяемая» (заменяемые — норма 5 лет);
* удалить из состава.

Подсказка под таблицей прямо говорит, чем задаётся срок: «срок оборудования
задают заменяемые запчасти (норма 5 лет) — от даты установки запчасти»;
если заменяемых запчастей нет — «собственного срока у оборудования нет».

При выборе модели в составе ГРП её запчасти подтягиваются из одноимённой
модели каталога (при отсутствии точного совпадения — по последнему слову
наименования), о чём программа сообщает в строке состояния. Если модели
в каталоге нет, программа предупреждает, что срока у оборудования не будет.

### 4. Замены (ремонт)

Журнал замен построен как бумажный ремонтный журнал: номер по порядку, дата
замены/ремонта, номер по схеме, запчасть в этом оборудовании, причина
замены/ремонта, наработка до замены/ремонта, остаточный ресурс после ремонта
(лет), документ-основание, ФИО ответственного, вид работ и примечание.
Других граф в таблице нет: влияние записи на срок службы видно в карточке
«Влияние на срок службы» при правке записи и в строке состояния («со сбросом
срока: N записей»), а при удалении записи, сбросившей срок, программа
предупреждает, что срок вернётся на прежний.

Дата замены/ремонта показывается как в документах — «ДД.ММ.ГГГГ»: в базе она
лежит так, как её ввели (ISO из импорта или «15.03.2024» из формы), и без
приведения к одному виду записи выглядели бы по-разному. Запись без дня
(«05.2023») показывается как записана.

Графы «Номер по схеме» и «Запчасть в этом оборудовании» собираются из
привязки записи: номер по схеме берётся у оборудования, а название запчасти —
из справочника (обозначение — из самой записи). У прежних записей из
«Лида.xlsx» привязки нет, поэтому эти графы у них пустые (прочерк).
Описание граф и полей — одно на таблицу, форму и чтение базы: `core/repair_journal.py`.

Графы ремонтного журнала заполняются в форме записи («Наработка до
замены/ремонта» — в часах, «Остаточный ресурс после ремонта, лет» — число лет
или «не нормируется», «Документ-основание» — акт, дефектная ведомость,
наряд-заказ, «Примечание» — свободная строка). Остаточный ресурс программа
подставляет сама и показывает в поле на виду: сброс срока возвращает запчасти
её норму (5 лет), полная замена оборудования — назначенный срок службы новой
единицы (паспорт при замене переносится). Если срок не назначен
(«не нормируется»), графа остаётся пустой. Подставленное значение правится
вручную, а вписанное пользователем не затирается.

Кнопка «➕ Добавить замену» открывает всплывающее окно замены запчасти:
слева оборудование ГРП, справа его запчасти (с нормой и признаком
заменяемости), внизу реквизиты записи (в том числе вид работ из списка:
«При ТР», «Замена по графику», «Замена после аварийной заявки» и другие),
графы ремонтного журнала и карточка «Влияние на срок службы». Кнопка «Заменить запчасть» доступна
только для запчастей с признаком «заменяемая»; кнопка «Заменить
оборудование полностью» показывает перечень запчастей и их нормы перед
подтверждением; «Закрыть» закрывает окно, а журнал за ним уже обновлён —
после замены окно остаётся открытым, чтобы подряд оформить несколько.

Карточка «Влияние на срок службы» записи:

* **только журнал** — запись попадает в журнал, сроки не меняются;
* **сбросить срок запчасти** — активная запись запчасти закрывается датой
  замены, создаётся новая, срок отсчитывается заново;
* **заменить оборудование целиком** — прежнее оборудование снимается,
  создаётся новое с датой замены, состав запчастей переносится с новыми
  датами.

Программа проверяет, что выбрана запчасть или оборудование, что дата
замены корректна и не раньше даты установки, что оборудование ещё
в эксплуатации; полная замена подтверждается отдельно. При правке
и удалении записи её влияние на срок откатывается.

Кнопка «✏ Редактировать» открывает реквизиты выбранной записи журнала —
графы журнала и прежние реквизиты «Лида.xlsx» (тип, модель, производитель,
номер запчасти): они не показываются в таблице, но нужны выгрузке в Excel
и отчёту, поэтому остаются доступными для правки. Там же доступно влияние
«только журнал», когда запись нужно поправить, не трогая сроки.

Журнал замен влияет на расчёт: по тексту вида работ, причины, модели
и номера запчасти находятся отказы, повреждения и некачественные ремонты
(списки маркеров — в `logic/algorithms.py`), они дают `N отказ`,
`N поврежд` и оценку ремонта. Дата последней замены по ГРП используется
как дата установки заменяемых запчастей, у которых своей даты нет.

### 5. Информация по отказам

Экран «Информация по отказам» открывается из меню действий с выбранным ГРП
и показывает отказы этого ГРП таблицей в порядке граф, заданном заказчиком:
номер записи, дата выявления, тип события (например, «нарушение работы
оборудования»), причина, критичность (словами: низкая, средняя, высокая),
устранён (да/нет), документ, куда отказ вносится, примечания. Других граф
в таблице нет. Свежие отказы стоят сверху.

Дата выявления показывается как в документах — «ДД.ММ.ГГГГ»: в базе она
лежит в ISO-виде, который пишет форма, и по нему же список упорядочен.
Незаполненная графа печатается прочерком.

Кнопки экрана: «➕ Добавить отказ», «✏ Редактировать», «🗑 Удалить»,
«📷 Открыть фото». Запись заводится и правится во всплывающем окне, где
критичность и признак устранения выбираются из списка («низкая, средняя,
высокая» и «да, нет»), тип события — свободная строка с подсказкой
(«нарушение работы оборудования», «аварийная остановка», «утечка газа»
и другие), а документ при создании записи подставлен как «Аварийный
журнал» — его можно заменить. Пустое значение списка значит «не указано».
Чужой текст в графы с ограниченным набором значений не записывается:
программа сообщает, что критичность — одно из трёх слов.

Примечания хранят номер акта и рекомендации, а фото прикладывается
кнопкой: снимок (или скан акта) сохраняется в базе вместе с записью,
показывается внешней программой по кнопке «📷 Открыть фото» и удаляется
вместе с записью. В графе «Примечания» фото не показывается — о нём
говорит отметка «📷 фото», поэтому список читается без содержимого снимков.
Фото лежит в базе, а не файлом рядом с программой: запись и снимок
переносятся вместе. В отчёт Word и в файл Excel отказы не выгружаются
и на расчёт сроков не влияют.

Описание граф и полей — одно на таблицу, форму и чтение базы:
`core/failure_log.py`.

### 6. Каталог оборудования и импорт PDF-альбома

Каталог — служебный ГРП, в наименовании которого есть слово «каталог»;
в списке выбора рабочего ГРП он не показывается и удалить его нельзя.
Каталог хранит модели оборудования с типовыми составами запчастей:

* таблица моделей: номер по порядку, наименование, срок службы (по
  минимальному остатку запчастей модели), число запчастей;
* панель «Запчасти модели» с теми же действиями, что и на рабочем экране
  (запчасти тоже нумеруются по порядку);
* добавление модели: только наименование, даты не нужны. Готовые
  наименования не подсказываются: модель вписывается своими словами, а
  программа проверяет, не заведена ли такая же — «РДС-32» и «рдс-32» это
  одна модель. Совпадение не сохраняется: сообщение называет уже имеющуюся
  строку каталога, к которой и добавляются запчасти;
* импорт из PDF: выбор файла альбома → разбор таблиц → наполнение
  справочника запчастей → создание моделей в каталоге → привязка состава;
  по завершении — сообщение с числом импортированных единиц.

Страницы альбома, на которых нарисована разборка узла («Корпус регулятора
давления газа РДС-32», «Мембрана регулятора давления газа РДС-32»),
моделями не становятся: их запчасти и так входят в состав самой модели,
а в каталоге они только смешивались бы с оборудованием. Признак —
`is_breakdown_page` в `integration/pdf_parts_import.py`: у страницы разборки
то же обозначение, что у модели, но название длиннее. Записи каталога
показываются свежими при каждом открытии раздела — отдельной кнопки
обновления нет.

В комплекте есть альбом `docs/Альбом запчастей по газу.pdf`; при пустом
каталоге `seed.py` импортирует его автоматически. Признак заменяемости
определяется по пометкам альбома и по списку характерных наименований
(мембрана, прокладка, пружина, седло и т. п.), обозначения переносятся
в состав оборудования.

### 7. Технические коэффициенты

Экран ведёт журнал технических диагностирований и историю коэффициентов
`№, Дата, A, B, C, K, n, u, m, r`.

Окно «Техническое диагностирование» собирает исходные данные и считает:

```
B = min(0,1; n / u)     n — оборудование с неисправностями, u — всего в работе
C = min(0,1; m / r)     m — разъёмные соединения с утечками, r — всего соединений
K = 1 − (A + B + C)     A — узел редуцирования и фильтры (0 или 0,1)
```

Есть кнопки «Отметить все» и «Снять отметки», живой предпросмотр
`K = 1 − (A + B + C)` с оценкой состояния, проверки «r должно быть больше
нуля» и «m не может быть больше r». Результат сохраняется в историю
и используется методикой «Алгоритм 2» как общий коэффициент `K общ`.

### 8. Техническое диагностирование

Отдельный экран (пункт меню «📋 Техническое диагностирование») — протокол
проверок выбранного ГРП, таблица в порядке граф:

`№, Дата, Оборудование, Проверяемый параметр, Режим (кПа), Допуск мин (кПа),
Допуск макс (кПа), Факт мин (кПа), Факт макс (кПа), Результат, Примечание`.

Запись — итог одной проверки одного параметра: «режим» — значение параметра
при проверке, «допуск мин/макс» — границы по документации, «факт мин/макс» —
что показала проверка. Результат («норма» или «отклонение от нормы»)
программа выводит сама: пока факт укладывается в допуск — «норма», как только
выходит за границу — «отклонение от нормы». В форме результат виден сразу
и выбирается вручную, если выход за допуск признан допустимым; выбранное
человеком значение программа не переписывает. Числа в кПа принимаются
с запятой и с точкой, описка в графе допуска не сохраняется — по этим числам
выводится результат.

Кнопки «Добавить проверку», «Редактировать» и «Удалить»; записи хранятся
в БД по каждому ГРП, свежие проверки сверху. Оборудование выбирается из
состава ГРП, но графа открытая: проверка читается и после того, как единицу
сняли. В расчёт остаточного ресурса и в журнал коэффициентов эти записи
пока не входят — коэффициенты `A`, `B`, `C` и «n», «m», «r» заполняются
в окне «Техническое диагностирование» на экране коэффициентов.

### 9. Экран «Остаточный ресурс»

Открывается пунктом «Расчёт алгоритмов» прямо в главном окне (кнопка
«Закрыть» возвращает рабочий экран ГРП). Заголовок — «Остаточный ресурс ·
<ГРП>», сверху — выбор методики (пять плиток слева), кнопки «Пересчитать»
и «Закрыть». Четыре вкладки:

**«Алгоритмы».** Для каждой методики:

* карточка-итог: название методики, остаток крупно, оценка,
  `T диагн.`, сколько элементов вошло в расчёт и какие не вошли и почему;
* карточка «Скоро нужно менять»: иерархическая таблица «элемент → его
  запчасти» с колонками «Категория, Норма, Возраст, Осталось, Истекает»;
  просроченные строки подсвечены; у элемента показывается запчасть, которая
  держит ресурс;
* карточка «Продление срока»: ползунок цели «Хочу продлить — сколько лет
  должно остаться от сегодня» (0…20 лет, шаг 1 месяц) и лестница замен —
  таблица «Категория, Запчасть, Срок сейчас, Срок после замены, Прирост».
  Программа отвечает на выбранную цель: «замен не нужно» (срок уже не
  меньше цели), «Нужно X — замен N» или «замены дают максимум Y»; ниже —
  подсказка, чем именно продлевается срок и сколько замен показано;
* карточка «Как посчитано: элементы и коэффициенты»: «Элемент, Категория,
  Норма, Возраст, Z база, K сост, K эксл, K рем, k повр, Осталось»
  и рекомендация под таблицей.

Шаг продления — замена запчастей слабого звена (самых изношенных), а не
замена оборудования. Прирост каждого шага — разница «срок до» и «срок
после» по всему ГРП. Если замена запчастей срок не двигает, программа
прямо об этом пишет: либо в расчёте нет заменяемых запчастей с нормой
5 лет, либо слабое звено держится не износом запчастей, а назначенным
сроком службы; дальше срок назначается диагностированием.

**«Срок замены».** Ползунок горизонта (0…5 лет) и таблица «Что нужно
заменить»: «Элемент, Тип, Запчасть, Норма запчасти, Возраст запчасти,
Осталось запчасти, Осталось элемента» — только то, что истекает в пределах
горизонта; просроченное и близкое подсвечены.

**«Коэффициенты».** Редактор весов и ручных поправок:

| Поле | Смысл | По умолчанию |
|---|---|---|
| α · отказ | вклад отказа в `k повр = 1 − α·N_отказ − β·N_повр` | 0,15 |
| β · повреждение | вклад повреждения (повреждения слабее отказов) | 0,10 |
| θ · условия | `K эксл = 1 − θ·(1 − Усл/Усл.норм)` | 0,10 |
| δ · ремонт | `K рем = 1 − δ·(1 − Рем/Рем.норм)` | 0,10 |
| K запаса | `T диагн = min(Z_ГРП × K_запаса; T_макс)` | 0,50 |
| T макс | верхняя граница междиагностического интервала, лет | 5,0 |

Ниже — ручные поправки `K сост`, `K эксл`, `K рем`, `k повр`: пустое поле
означает «считать по формуле методики», заполненное — «взять введённое
значение и пометить в расчёте как заданное вручную». Кнопка «Вернуть
методические» сбрасывает всё, «Пересчитать с этими коэффициентами»
применяет; значение вне диапазона 0…1 не принимается, поле подсвечивается.

Под редактором — таблица «Как получились коэффициенты по каждому элементу»
с формулой в последней графе; слабое звено, нулевой ресурс, пропущенные
элементы и ручные поправки выделены.

**«Исходные данные».** Карточка журнала технической диагностики
(`A`, `B`, `C` → `K общ`, с примечанием, если хранимое значение K
расходится с формулой) и карточка «Что поступило в расчёт по каждому
элементу»: «Элемент, Категория, S нач, Источник, Запчасти, Z база, Отказы,
Повреж., Ремонт, В расчёте» — в последней графе видно, вошёл элемент
в расчёт или нет и почему.

Экран расчёта показывает замечания к данным и результату:
нет критических элементов (проверить наименования); нет данных о запчастях
и нормах — считается упрощённый календарный вариант; пуст журнал
диагностики — `K общ = 1` и оценка завышена; пуст журнал замен —
`N отказ = N поврежд = 0` и `k повр = 1`; журнал покрывает не все элементы;
у заменяемых запчастей нет даты установки — принята дата последней замены
по ГРП; нормативный срок отработан — ресурс принят нулём; ресурс исчерпан
поправками; некритические элементы не вошли в расчёт.

### 10. Методики расчёта

Внутренняя нумерация (0–4) не совпадает с пользовательской (1–5) —
в интерфейсе и отчётах всегда используется пользовательская.

| Методика | Название | Что считает |
|---|---|---|
| Алгоритм 1 | Утверждённая методика | `Z = S_назн − S_факт` по всем элементам; итог — среднее арифметическое |
| Алгоритм 2 | Среднее арифметическое | среднее `Z` × общий коэффициент `K общ = 1 − (A + B + C)` из журнала диагностик |
| Алгоритм 3 | REGION-gaz (слабое звено) | минимум по критическим элементам, полный набор коэффициентов |
| Алгоритм 4 | Скорректированный (наработка + 4 коэффициента) | **основная методика**: приоритет фактической наработки, некратные замены, `T диагн.` |
| Алгоритм 5 | Календарный (срок полной проверки) | база — остаток от 20 лет, далее те же коэффициенты и слабое звено |

Источник каждой методики печатается рядом с названием; документы лежат
в `docs/`. Расчёт одной методики по элементу:

```
Z база   — базовый ресурс элемента
Z эл     = Z база × K сост × K эксл × K рем × k повр      (не меньше нуля)
результат = min(Z эл) по критическим элементам           (Алгоритмы 3, 4, 5)
          = среднее Z эл                                 (Алгоритмы 1, 2)
T диагн. = min(результат × K запаса; T макс)
```

База `Z` берётся по первому подходящему из вариантов: явная оценка
(`z_base`), затем наработка по часам или циклам, затем состояние запчастей
по диагностике, затем экспертная оценка по запчастям
`Z = S нач − S факт`, затем календарный резерв `S нач − возраст`. Если
база считается по запчастям, `Z база` элемента — минимум по его
заменяемым запчастям: принцип слабого звена работает уже внутри элемента.

Коэффициенты: `K сост` — по протоколу диагностики, `K эксл` — по режимной
карте, `K рем` — по качеству ремонта, `k повр` — по числу отказов
и повреждений; при отсутствии данных коэффициент равен 1. Нормы по
умолчанию: 5 лет для заменяемых запчастей, 20 лет для остальных позиций
и для срока полной проверки оборудования (`core/config.py`).

`K сост` считается по строкам раздела «Техническое диагностирование»:
оборудование в протоколе опознаётся тем же признаком, что и элемент
(регулятор, ПЗК, ПСК, фильтр, арматура), поэтому протоколы и расчёт сходятся
без отдельного справочника. Каждое фактическое значение — отдельная проверка
(протокол даёт факт минимума и факт максимума: 10 строк регулятора — это
20 проверок), отклонение берётся от режима проверки и делится на полосу
допуска `допуск макс − допуск мин`, а коэффициент — `1 − Σотклонений / число
проверок`. У элемента без числовых проверок (только «герметичность») и без
протоколов вовсе `K сост = 1` — об этом расчёт сообщает замечанием.

Слабое звено — элемент с наименьшим ресурсом; если у нескольких элементов
дата истечения совпадает, в слабые звенья попадают все, а рядом
указывается запчасть, которая держит ресурс. Градация: ресурс исчерпан,
критический (менее года), низкий (1–3 года), средний (3–5 лет), высокий
(более 5 лет) — с текстовой рекомендацией.

### 11. Отчёт Word и форма 6.2

Отчёт формируется кнопкой «Отчёт по ГРП (Word)» и состоит из:

1. титульного листа — организация, отдел, «ОТЧЁТ», реквизиты (объект
   оценки, ID объекта, шифр, редакция, дата формирования, режим доступа
   «ДСП»), город и год, колонтитул с номером страницы;
2. раздела 1 «Сведения о ГРП» — таблица «Показатель / Значение»
   по паспорту объекта;
3. раздела 2 «Результаты расчёта остаточного ресурса» — форма 6.2
   по двум методикам: «Алгоритм 3» и «Алгоритм 4»;
4. подписей — исполнитель, проверил, утвердил, дата выдачи.

Форма 6.2 — 23 строки и пять категорий критических элементов (регулятор,
ПЗК, ПСК, фильтр, арматура): базовые ресурсы категорий, `K сост` по
категориям, общие `K усл`, `K рем`, `k повр`, итоговые ресурсы категорий,
слабое звено, остаточный ресурс ГРП, срок следующего диагностирования
в годах и месяцах и рекомендуемая дата. Числа формы сверяются тестом
`tests/test_report_form62.py` с результатом расчёта, поэтому отчёт
не расходится с экраном. Параметры расчёта в отчёт передаются те же, что
заданы на экране расчёта.

### 12. Выгрузка Excel

Кнопка «📥 Обновить Excel» на экране замен (отдельного пункта меню нет)
пересобирает `Замены.xlsx` рядом с программой:
на каждый рабочий ГРП — лист «Ремонт <тип ГРП>» с шапкой формы (дата
замены, номер запчасти, тип оборудования, модель, производитель, тип
и номер объекта, вид работ, причина, ФИО руководителя). Даты приводятся
к виду «М.ГГГГ». Посторонние листы файла сохраняются, служебные каталоги
не выгружаются. Файл обновляется автоматически после каждой операции
с заменами; если Excel занят, программа сообщает об этом и не падает.

### 13. Хранение данных

Все таблицы создаются автоматически при первом запуске
(`db/database_pg.py`), повторный запуск их не ломает: используются
`CREATE TABLE IF NOT EXISTS` и миграции `ADD COLUMN IF NOT EXISTS`.

| Таблица | Что хранит |
|---|---|
| `grp` | ГРП: тип, число линий, сроки и все поля паспорта объекта |
| `equipment` | единицы оборудования в составе ГРП: дата монтажа, дата снятия (ставится заменой целиком, в интерфейсе не показывается) и паспортные сведения (тип, изготовитель, ДУ, количество, номер по схеме, назначенный срок, наработки, примечание) |
| `parts` | справочник запчастей: наименование, норма срока службы, признак заменяемости |
| `equipment_parts` | состав оборудования: какие запчасти установлены, даты, обозначение; активная запись одна |
| `technical_coefficients` | журнал технических диагностирований (A, B, C, K, n, u, m, r) |
| `replacements` | журнал замен запасных частей и влияние записи на срок: реквизиты «Лида.xlsx» и графы ремонтного журнала (наработка до замены, остаточный ресурс после ремонта, документ-основание, примечание) |
| `failures` | отказы ГРП: дата выявления, тип события, причина, критичность, признак устранения, документ, примечания и приложенное фото |
| `diagnostic_checks` | протокол технического диагностирования: дата, оборудование, проверяемый параметр, режим, допуск мин/макс, факт мин/макс, результат и примечание |

Журнал замен намеренно не связан внешними ключами с оборудованием
и запчастями: это исторический документ, он должен переживать удаление
оборудования. Справочник запчастей общий для всех ГРП, поэтому норма,
исправленная в одном месте, действует везде.

### 14. Демонстрационные данные

`seed.py` создаёт базу, таблицы, справочник заменяемых запчастей
и приводит нормы к правилу «5 лет / 20 лет» (значения, заданные вручную,
не трогаются). `seed.py --demo` дополнительно создаёт четыре
демонстрационных ГРП — сценария замены запчастей:

| Сценарий | Оборудование | Как меняются запчасти |
|---|---|---|
| №1 | ГРП 2008 г. | часть запчастей с истёкшим сроком (слабое звено — 0 лет) |
| №2 | ГРП 2012 г. | ресурс запчастей менее года |
| №3 | ГРП 2016 г. | ресурс запчастей в норме |
| №4 | ГРП 2021 г. | замены недавние, ресурс больше 3 лет |

Единицы оборудования стоят с даты установки и не меняются — различаются
сценарии только датами замен запчастей, причём у каждой запчасти дата своя:
раскладка идёт по всему ГРП, ни одна пара дат не совпадает. Поэтому
остаточные ресурсы элементов различаются и слабое звено в расчёте
получается ровно одно.

Паспортные сведения демо-единиц (`_demo_card` в `seed.py`) выводятся
из названия модели: тип, изготовитель и условный проход разбираются
из заводского обозначения («… КРОН-150»), фактическая наработка считается
по сроку эксплуатации. Это демонстрационные числа для наглядности граф,
а не паспорт реального изделия. Сценарии, созданные прежней версией, при
повторном запуске не обновляются — чтобы заполнить у них паспортные графы,
нужен полный сброс (`--reset-demo`).

Сценарии создаются один раз: повторный запуск находит их по названию
и ничего не меняет, поэтому правки дат, внесённые вручную, сохраняются.
Каталог оборудования и рабочие ГРП пользователя демо-данные не затрагивают.
Полный сброс: `py -X utf8 seed.py --demo --reset-demo`.

### 15. Чего в программе нет

* Нет авторизации, ролей и прав доступа: доступ к базе определяется только
  учётной записью PostgreSQL.
* Нет режимных карт и телеметрии: наработка по часам и циклам, а также
  коэффициент условий эксплуатации заполняются вручную — иначе `K эксл`
  принимается равным 1.
* Нет выгрузки в PDF и печати из программы: отчёт формируется в Word,
  журнал замен — в Excel.
* Нет загрузки данных из Excel обратно в базу: Excel — только выгрузка.
* Отказы не попадают ни в Word-отчёт, ни в файл Excel и не участвуют
  в расчёте сроков: экран «Информация по отказам» — отдельный журнал.
* Протокол технического диагностирования (режим, допуск и факт в кПа) входит
  в расчёт только через `K сост` — по отклонениям от режима и полосе допуска.
  Коэффициенты `A`, `B`, `C` и «n», «m», «r» окна «Техническое
  диагностирование» в расчёт не входят: это отдельная, более ранняя оценка
  состояния, и профиль ГРП она не меняет.
* Нет сетевого режима и синхронизации между машинами: общая база
  PostgreSQL — единственная точка обмена.

```bat
git clone https://github.com/Kurome00/grp_analitic.git
cd grp_analitic
py -m pip install -r requirements.txt
```

## Настройка базы данных

При первом запуске база `grp_analyzer` и все таблицы создаются
автоматически. Нужно только, чтобы:

1. PostgreSQL был **запущен** (в `services.msc` — служба `postgresql-x64-16`).
2. У пользователя `postgres` был известен пароль, а у роли — право
   создавать базы.

Пароль задаётся переменными окружения. По умолчанию используется
`postgres` / `postgres`:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `GRP_DB_HOST` | `localhost` | адрес сервера |
| `GRP_DB_PORT` | `5432` | порт |
| `GRP_DB_USER` | `postgres` | пользователь |
| `GRP_DB_PASSWORD` | `postgres` | пароль |
| `GRP_DB_NAME` | `grp_analyzer` | имя базы |

Задать их разово в окне cmd:

```bat
set GRP_DB_PASSWORD=свой_пароль
```

Или постоянно — «Свойства пользователя» → «Переменные среды».

## Если не запускается

**`UnicodeDecodeError: 'utf-8' codec can't decode byte ...`**
База не создана, и PostgreSQL отвечает об ошибке в кодировке,
нечитаемой для Python. База создастся сама при следующем запуске;
если не помогло — проверьте, что служба PostgreSQL запущена,
и что пароль пользователя задан через `GRP_DB_PASSWORD`.

**`password authentication failed for user "postgres"`**
Пароль в `DB_CONFIG` не совпадает с паролем на сервере. Задайте
`GRP_DB_PASSWORD`.

**`permission denied to create database "grp_analyzer"`**
У роли нет права `CREATEDB`. Выдайте его:

```sql
ALTER USER postgres CREATEDB;
```

**`could not connect to server: ... port 5432`**
Сервер не запущен или listening на другом порту. Проверьте службу
и переменную `GRP_DB_PORT`.

**`ModuleNotFoundError: psycopg2` / `docx` / `pdfplumber`**
Не установлены зависимости: `py -m pip install -r requirements.txt`.

**Окно открылось, но ГРП нет**
Демо-сценарии создаются только при первом запуске с ключом `--demo`.
Создать их заново: `py -X utf8 seed.py --demo --reset-demo`.
См. раздел «Запуск».


Все сроки службы считает один модуль — `core/lifetimes.py`. Разбор дат,
возраст, норма и остаток живут там, поэтому интерфейс и Word-отчёт
показывают одно и то же число. Менять год (365.25 дней) или средний
месяц (30.44 дня) следует только там.

## Тесты

```bat
py -X utf8 -m unittest discover -s tests
```

343 теста не требуют PostgreSQL и не создают файлов: проверяются разбор
дат, перевод в годы и месяцы, остаток срока (в том числе просрочка),
слабое звено, продление срока заменой запчастей, коэффициенты, форма 6.2,
согласованность расчёта между ядром, моделью и интерфейсом и описание полей
паспорта — и ГРП (`core/grp_passport.py`), и единицы оборудования
(`core/equipment_card.py`: неназначенный срок службы, узнавание модели по
наименованию),
ремонтного журнала (`core/repair_journal.py`: порядок граф, остаточный
ресурс после ремонта), журнала отказов (`core/failure_log.py`: порядок
граф, слова критичности и признака устранения, отметка о фото) и протокола
технического диагностирования (`core/diagnostic_log.py`: порядок граф, числа
в кПа с запятой и точкой, вывод результата по допуску и факту).
`K сост` из строк протокола — в `tests/test_k_state_protocol.py`: две
проверки на строку (минимум и максимум), полоса допуска в знаменателе
и пропуск строки без режима.

## Сборка .exe

```bat
py -m pip install pyinstaller
py -m PyInstaller GRP_Analyzer.spec
```

Готовый файл — в `dist\GRP_Analyzer.exe`.

> Требуется доступ к базе на машине, где запускается `.exe`:
> PostgreSQL должен быть установлен и настроен так же, как описано выше.

Куда `.exe` пишет и что ищет:

| Что | Где |
|---|---|
| база данных | PostgreSQL, как описано выше |
| `docs\` с методиками | рядом с `.exe` — в сборку не входит, весит ~75 МБ |
| `icon.png` | внутрь `.exe` (PyInstaller) или рядом, если запускать из исходников |
| `Замены.xlsx` | рядом с `.exe`; в сборку попадает, только если файл есть на момент сборки |
| рабочие выгрузки, логи | `data\` рядом с `.exe` |

Папка `.exe` должна быть доступна на запись — туда складываются логи
и выгрузки Excel. Установка в `Program Files` без прав администратора
для этого не подходит.
