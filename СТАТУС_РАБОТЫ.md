## Сделано и проверено

### 1. Пути PyInstaller (готово, проверено имитацией frozen)
`core/config.py`: `_app_dir()`, `_resource_dir()`, `PROJECT_ROOT`, `RESOURCE_DIR`,
`resource_path()`, `docs_path()`. `PROJECT_ROOT` для frozen — папка `.exe`,
`RESOURCE_DIR` — `sys._MEIPASS`. `main_pg.py` ищет иконку через `resource_path()`,
`seed.py` — PDF через `docs_path()`, `integration/excel_sync.py` пишет в `PROJECT_ROOT`.
`GRP_Analyzer.spec`: optional `icon.png`/`Замены.xlsx`, hiddenimport `ui.window_utils`;
`docs/` намеренно не встроен (75 МБ), ищется рядом с `.exe`.
`docs_path()` при отсутствии файла возвращает путь рядом с программой (не `_MEIPASS`),
чтобы в сообщении об ошибке был виден реальный путь.

### 2. Расхождение UI и Word (готово, отчёт проверен генерацией)
`generate_grp_docx(..., params=None, coefficients=None)` — `integration/word_report_pg.py`.
`AlgorithmsWindow(..., params=None, on_params=None)` — `ui/algorithms_view.py`;
callback вызывается после успешного расчёта, значения копируются.
`GRPAppPG.calc_params` + `_remember_calc_params()` — `ui/views_pg.py`;
окно расчёта больше не пересоздаётся, Word-экспорт передаёт `self.calc_params`.

Проверено на ГРП №3 (23 единицы оборудования) три варианта вызова:
- `params=None` — 61 489 байт, примечание «рекомендациям методики»;
- рекомендуемые `AlgorithmParams()` — тот же результат;
- изменённые параметры (`α=0,25, β=0,15, θ=0,20, δ=0,20, K_запаса=0,7`) — в таблице
  отчёта печатаются фактические значения, примечание заменено на «заданы в окне
  расчёта». Расхождения с экраном больше нет.

### 7. Найдено и исправлено при проверке
- **`integration/word_report_pg.py`: `_note()` не принимал `space_after`** — новое
  примечание о соответствии нумерации методик роняло экспорт `.docx` с
  `TypeError: _note() got an unexpected keyword argument 'space_after'`.
  Отчёт не генерировался вообще ни разу после правок, поэтому ошибка и не всплыла.
  Теперь у `_note()` есть параметр `space_after` (по умолчанию 6, как было).
- `db/database_pg.py:add_part` — `get_part_by_name` возвращает `Optional[Tuple]`,
  при отсутствии строки был `TypeError: 'NoneType' object is not subscriptable`.
  Теперь явный `ValueError` с подсказкой про регистр/пробелы.
- Тот же баг в двух местах `ui/views_pg.py` (`_toggle_part_replaceable`,
  каталог) — добавлена проверка `part and part[3]`.

## Не доделано

### A. Данные демо-базы не позволяют посчитать срок
Расчёт отрабатывает без ошибок, но у оборудования в базе `install_date = NULL`,
поэтому все методики возвращают «нет элементов с известным нормативным ресурсом».
Это данные, а не код: нужна база с заполненными датами установки
(`seed.py --demo` этого не делает). Проверить значения методик на ненулевом
результате пока не на чем.

### B. Не проверено вручную
1. Tkinter-GUI не открывался. Проверить окно расчёта: значения подставляются
   из сохранённых, callback срабатывает, невалидный ввод не затирает прошлое.
2. PyInstaller-сборка не запускалась. `GRP_Analyzer.spec` правился вручную,
   `docs/` намеренно не входит — проверить, что каталог оборудования ищет
   методики рядом с `.exe`.
3. `seed.py --demo --reset-demo` после правок `_actual_life` не запускался
   (команда перезаписывает демо-данные — нужно подтверждение).

### C. Решения, которые стоит подтвердить
1. Год = 365.25 дней, месяц = 30.44. Это выбрано, чтобы свести UI и отчёт;
   если методика требует 365 дней — правится одна константа в
   `core/lifetimes.py`.
2. `EQUIPMENT_NORMS` в `config.py` — все 11 записей имеют норму 20 лет
   (тесты это зафиксировали). Если часть записей должна быть 8/12 лет,

3. Нумерация методик 1–5 (внутри 0–4) зафиксирована тестами и в отчёте
   сопоставлена с исходными документами. Если приложение перенумеруют —
   правится `algo_number()` и `ALGORITHM_SOURCES`.
